## This archive carries no Firebase project

There is no connection to any Firebase account in this code. Nothing will
work until you create your own project and fill in six values.

1. Create a Firebase project **in an account the hospital owns**, upgrade it
   to the **Blaze** plan, and attach the hospital's payment method.
2. Enable **Authentication → Email/Password**.
3. Create **Firestore** and **Storage**, both in region `asia-south1`.
   This region cannot be changed later — the Cloud Functions are pinned to it.
4. Register a web app (the `</>` icon under **Project settings → General →
   Your apps**) and copy its six config values into
   [js/firebase-config.js](js/firebase-config.js).

That file is the only place the project is named. The patient portal and the
waiting-room display read from it too. None of the six values is a secret; a
Firebase web config is public by design, and the data is protected by the
security rules plus sign-in. That is why the rules must be deployed before
anyone is given a login.

If `projectId` is left empty, the app renders a "Firebase is not configured"
page and refuses to start rather than writing somewhere unintended.

## Deploy

```bash
npm install
cd functions && npm install && cd ..

firebase login
firebase use <your-project-id>

firebase functions:secrets:set BACKUP_BUCKET        # required
firebase functions:secrets:set CALENDAR_FEED_SECRET # required

npm run deploy
```

`npm run deploy` publishes the security rules, **the composite indexes**, the
storage rules, the nine core Cloud Functions and the built website, in that
order. Then wait in **Firestore → Indexes** until every index reads *Enabled* — there
are 46 of them and they take a few minutes to build. Several screens query on
an equality filter plus a sort on another field and fail outright until the
matching index exists, and that failure never appears locally.

Finally add your domain under **Authentication → Settings → Authorized
domains**, or every sign-in is rejected.

Handbook Part 6 covers the Hostinger route, where Hostinger serves the files
and Firebase still provides the database, sign-in and functions.

## Run it locally

```bash
npm start      # Firebase emulators + hosting → http://127.0.0.1:5000
npm run seed   # demo staff, patients, beds and stock in the emulator
npm test       # 39 unit and backend tests
npm run build  # refresh dist/ after editing any file
```

On `localhost` the app switches itself to the emulators and never touches a
live project, so `js/firebase-config.js` can stay empty for development.
Serving the folder with a plain static server instead of `npm start` gives
**"Network error"** at sign-in, because the emulators are not running.

Java is required by the emulators and is bundled at `.runtime/java`, which is
not in this archive — on a fresh machine run `npm run setup:java` once.

Local sign-in after seeding: `admin@jyothsna.test` / `DemoHospital123!`, and
the same password for `doctor@`, `nurse@`, `reception@`, `billing_staff@`,
`pharmacist@`, `lab_technician@` and `owner@` at that domain. These exist only
inside the emulator; `scripts/seed.cjs` pins the emulator hosts and cannot
reach a live project.

## What is deliberately not here

| Not included | Why |
| --- | --- |
| `node_modules`, `functions/node_modules` | `npm install` restores them |
| `.runtime` | Bundled Java, ~180 MB; `npm run setup:java` fetches it |
| `dist` | Generated by `npm run build` |
| Any Firebase project id, key or bucket | You supply them in `js/firebase-config.js` |
| Any account, token or password | Nothing of the developer's remains in this code |

`npm run package:handover` rebuilds this archive. It scans every text file for
credential-shaped values first and refuses to write the zip if it finds one.

## Before the hospital starts using it

The handbook's Part 10 is the full list. The four that matter most:

- Deploy the indexes and wait for every one of the 46 to go green.
- Delete every demo account in **Authentication → Users** — anything ending
  `@example.local` or `@jyothsna.test`.
- Set real bed tariffs, service prices and package prices. Pharmacy prices are
  **GST-inclusive**: the taxable value is back-calculated per line and the tax
  is split equally into CGST and SGST.
- Decide what to do about `queue-display.html`. It reads tokens with no
  sign-in, and those records carry patient names. Show token numbers only, or
  put the page behind authentication.
